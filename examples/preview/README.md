# PDF Preview

Demo application for Lib-PDF, following the structure used by the other HuxerUI libraries:

```text
examples/preview/
  CMakeLists.txt
  HuxerUIProject.cmake
  src/app.cpp
  resources/raw/guide.pdf
  resources/strings/default.properties
  platform/windows/
  platform/macos/
  platform/linux/
  platform/android/
  platform/ios/
```

The demo opens a bundled three-page field guide at startup. Use **Open PDF** to
choose a local document, or **Load sample** to return to the guide. Password PDFs
show a secure password field and **Unlock** button. Controls include page
navigation, 25–300% zoom (click the percentage to reset), clockwise rotation,
annotation visibility, and light/dark themes.

The **Document** panel displays metadata and searches the current page. An active
query is repeated when changing pages. The **Page text** panel supports text
selection and copying, with a 12,000-byte display limit. Search reports match
counts; it does not draw highlights. File opening, parsing, rendering, text
extraction, and search use the library's `UsePdf`/`PdfSession` asynchronous API.
The app owns `State<PdfSource>` and `State<PdfOptions>`, composes `PdfPage`, and
awaits typed results for text/search. It has no manual PDF parsing or RunWorker
pipeline. Display controls are application-owned intent; status and the published
page are read from `Snapshot()`.
The sample includes a landscape page and a yellow annotation that can be toggled.

## Standalone build

From the repository root:

```sh
cmake -S examples/preview -B build-demo -DHUXERUI_HOME=/path/to/HuxerUI
cmake --build build-demo --config Release --target example_pdf --parallel
```

On Windows, run `build-demo/Release/example_pdf.exe`. On other desktops, locate
`example_pdf` or the **PDF Preview** app bundle in `build-demo`. The Windows
PDFium DLL and the compiled application resource package are staged by CMake.
Keep the resource package with the executable when copying the built demo.

Offline builds can also pass
`-DHUXERUI_PDF_FETCH_PDFIUM=OFF -DHUXERUI_PDF_PDFIUM_ROOT=/path/to/pdfium`.
The default macOS SDK requires macOS 13 or later.

Alternatively, enable `HUXERUI_PDF_BUILD_EXAMPLES=ON` in the root library build;
the same `example_pdf` target is then built under `build/examples/preview`.

`HuxerUIProject.cmake` exposes app plan metadata for HuxerUI tooling, and compiler-free
library-graph discovery is supported. The demo provides Windows, macOS, Linux,
Android, and iOS Simulator entry points. A Web preview is not supplied.

## Version and packaging

The repository root `VERSION` file is the single source of truth for the
application version. CMake reads it for `project(...)` and for the compiled
`PDF_PREVIEW_VERSION` / `PDF_PREVIEW_PLATFORM` labels shown in the window title
and status bar (`v0.2.0 · Windows`). It also flows into:

- the Windows executable's `FileVersion`/`ProductVersion` resource,
- the macOS `CFBundleShortVersionString`/`CFBundleVersion`,
- Android `versionName` and the derived `versionCode`
  (`major * 10000 + minor * 100 + patch`),
- the iOS `CFBundleShortVersionString`/`CFBundleVersion` and the
  `MARKETING_VERSION` guard in `platform/ios/Config/Base.xcconfig`,
- a staged `VERSION` file next to the built desktop executable.

The library exposes the same value through `huxerui::pdf::Version()`.

Release archives are named `<app>-<version>-<os>-<arch>`, for example
`pdf-preview-0.2.0-linux-aarch64.tar.gz`, and each one contains a `VERSION`
file. Release notes for a tag are read from `docs/releases/<tag>.md` when the
file exists.

## Mobile builds

Android and iOS builds use the checked-in HuxerUI platform shells and the same
`example_pdf` target. PDFium is downloaded automatically for the selected Android
ABI or iOS architecture unless `HUXERUI_PDF_PDFIUM_ROOT` is supplied.

```sh
# Build the HuxerUI CLI at the repository root first.
cd examples/preview
../../build-huxerui-cli/huxerui package android --profile debug --source /path/to/HuxerUI
```

The Android APK is staged under `dist/android` and contains `libexample_pdf.so`,
`libhuxerui.so`, `libpdfium.so`, and the packaged demo resources. Release APKs use
the debug signing key so they remain installable as a demo.

The iOS project lives in `platform/ios/example_pdf.xcodeproj`. Build it with
`huxerui package ios --profile debug --source /path/to/HuxerUI` or open it with
`huxerui open ios --source /path/to/HuxerUI`. The embedded PDFium dylib is copied
into the app's `Frameworks` directory. The pinned PDFium iOS SDK requires iOS 17.

The `Multi-Platform Release` workflow publishes versioned artifacts for Windows
x64, Linux x86_64/aarch64, macOS arm64/x86_64, Android arm64-v8a/x86_64 and the
iOS Simulator, for tags matching `v*` or a manual dispatch.

The PDF resource is generated by `python scripts/generate_demo.py` from the root;
Python is not required to build or run the demo. The resource has no runtime
dependency on the source tree or the test fixtures.

When building from the root with `HUXERUI_PDF_BUILD_TESTS=ON`,
`HUXERUI_PDF_BUILD_EXAMPLES=ON`, and `HUXERUI_BUILD_TESTING_LIBRARY=ON`, CTest also
runs `pdf.demo` against this application and its actual packaged resources. It
covers initial loading, search, page changes, zoom, rotation, annotation toggles,
text inspection, theme switching, and reloading the sample without opening windows.
